## 1.1.0

* **Launch at Startup (auto-start on user login) across macOS, Windows, and Linux:**
  * **Dart API:** added `LaunchAtStartupConfig`, `LaunchAtStartupState`, `LaunchAtStartupStatus` (`enabled`, `disabled`, `requiresApproval`, `disabledByUser`, `disabledByPolicy`, `unsupported`), `LaunchAtStartupBackend`, `MacOSLaunchAtStartupMode` (`automatic`, `appService`, `launchAgent`), and controller methods `getLaunchAtStartupState`, `isLaunchAtStartupEnabled`, `setLaunchAtStartup`, `configureLaunchAtStartup`, and `openLaunchAtStartupSettings` on `XueHuaNaviteWindowManager` (`NativeWindowController`). Zero-boilerplate defaults resolve bundle identifiers, display names, and executable paths automatically from the running process.
  * **macOS (`Swift 5.9+` / `ServiceManagement`):** supports Apple's `SMAppService.mainApp` (`macOS 13.0+`, App Sandbox and Mac App Store compatible without extra entitlements) and user `LaunchAgent` plists (`~/Library/LaunchAgents/<identifier>.plist`, supporting custom CLI `arguments` and `macOS 12.0` for unsandboxed apps). `openLaunchAtStartupSettings()` opens `System Settings > General > Login Items` via `SMAppService.openSystemSettingsLoginItems()`.
  * **Windows (`C++17` / pure Win32 Registry & AppModel):** manages `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` with proper `CommandLineToArgvW`-compatible argument quoting, inspects and synchronizes `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run` so user toggles in Task Manager / Settings (`disabledByUser`) and Group Policy blocks (`disabledByPolicy`) are accurately reported instead of misreported as enabled, and supports MSIX packaged apps via `AppModel\SystemAppData` `StartupTask` `State` (built cleanly under `/W4 /WX` and `_HAS_EXCEPTIONS=0` with zero C++/WinRT runtime overhead). `openLaunchAtStartupSettings()` launches `ms-settings:startupapps`.
  * **Linux (`C++14` / GLib & Freedesktop XDG Autostart):** manages `$XDG_CONFIG_HOME/autostart/<identifier>.desktop` with two-layer Desktop Entry `GKeyFile` + `Exec=` field-code and shell-quoting escaping, honors `Hidden=true` and `X-GNOME-Autostart-enabled=false` as `disabledByUser`, and resolves `$APPIMAGE` (avoiding transient `/tmp/.mount_*` paths) and `$FLATPAK_ID` (`flatpak run <id>`) before falling back to `/proc/self/exe`.
* **Application-level channel calls without an attached window:** `getLaunchAtStartupState`, `setLaunchAtStartup`, and `openLaunchAtStartupSettings` execute before window resolution on macOS, Windows, and Linux so background/tray or pre-window startup checks never fail with `NO_WINDOW`.
* **Maximized / Fullscreen Geometry Transitions & Windows Accessibility Stability:**
  * **Windows (`WM_NCCALCSIZE` / `WS_MAXIMIZE` / `ui::AXTree`):** `configure`, `setBounds`, `setSize`, `setPosition`, and `center` now restore a maximized (`IsZoomed`), minimized (`IsIconic`), or fullscreen `HWND` to normal windowed state before applying target bounds, intersect `WM_NCCALCSIZE` client rects with `rcWork` so client bounds never exceed outer window bounds, focus and size the child `FlutterWindowsView` (`HWND`) instead of stealing focus onto the outer container window, and dispatch `EventChannel` notifications asynchronously at top-level on the Win32 message pump instead of re-entering Dart inside `WndProc` / `WM_NCHITTEST` / UIAutomation queries.
  * **Linux (`GTK3` / X11 & Wayland):** `configure`, `setBounds`, `setSize`, `setPosition`, and `center` now unfullscreen, unmaximize, and deiconify before applying windowed bounds, update `gtk_window_set_default_size`, re-apply pending geometry once EWMH / Wayland confirms the unmaximize state transition, and avoid `gtk_widget_show_all` re-showing hidden custom `GtkHeaderBar` widgets.
  * **Flutter Semantics (`WindowCaption` & Example Studio):** kept widget and `SemanticsNode` tree structures invariant across resize/minimize layout passes (`WindowCaption`, `StatusTelemetryCard`, `EventStreamPanel`, `WindowStudioDashboard`) to prevent `ui::AXTree` desynchronization on Windows.
* **Native Multi-File Standard Directory Architecture across macOS, Windows, and Linux:**
  * **macOS (`SwiftPM` / `macos/`):** decomposed monolithic Swift files into standard PascalCase domain subdirectories under `macos/xue_hua_navite_window_manager/Sources/xue_hua_navite_window_manager/` (`Dispatch/XueHuaWindowMethodDispatcher.swift`, `Window/XueHuaWindowConfigurator.swift`, `Window/XueHuaWindowAppearance.swift`, `Window/XueHuaWindowGeometry.swift`, `Window/XueHuaWindowDelegate.swift`, `Startup/XueHuaLaunchAtStartup.swift`, `Startup/XueHuaLaunchAgentStore.swift`, `Startup/XueHuaAppServiceBridge.swift`, `XueHuaNaviteWindowManagerPlugin.swift`). Enforced 0 compiler/SwiftPM/linker warnings with `tool/check_macos_native_warnings.sh`.
  * **Windows (`C++17` / `windows/`):** decomposed 2,100+ line monolithic source and header files into dedicated modular sources under `windows/src/` (<450 lines each: `window_geometry_logic.h`, `launch_at_startup_logic.h`, `method_call_utils.h`/`.cpp`, `window_frame_controller.cpp`, `window_message_handler.cpp`, `window_method_dispatcher.cpp`, `launch_at_startup_windows.cpp`, `xue_hua_navite_window_manager_plugin.h`/`.cpp`, `xue_hua_navite_window_manager_plugin_c_api.cpp`) and modularized tests under `windows/test/` (`window_geometry_logic_test.cpp`, `launch_at_startup_windows_test.cpp`, `window_plugin_smoke_test.cpp`), preserving the public C-API header at `windows/include/xue_hua_navite_window_manager/xue_hua_navite_window_manager_plugin_c_api.h` and maintaining 0 warnings under `/W4 /WX`.
  * **Linux (`C++14` / `linux/`):** decomposed 2,000+ line monolithic plugin files into dedicated modular sources under `linux/src/` (`fl_value_utils.h`/`.cc`, `window_logic.h`/`.cc`, `launch_at_startup_logic.h`/`.cc`, `launch_at_startup_linux.cc`, `window_frame_controller.cc`, `window_hooks_and_events.cc`, `window_interactive_drag.cc`, `window_method_dispatcher.cc`, `plugin_internal.h`, `xue_hua_navite_window_manager_plugin_private.h`, `xue_hua_navite_window_manager_plugin.cc`) and modularized tests under `linux/test/` (`window_logic_test.cc`, `launch_at_startup_logic_test.cc`, `linux_plugin_lifecycle_test.cc`), preserving the public GObject header at `linux/include/xue_hua_navite_window_manager/xue_hua_navite_window_manager_plugin.h` and maintaining 0 warnings under strict `-Wall -Werror -Wextra -Wpedantic`.

The app and the plugin still target macOS 12.0. `tool/check_macos_native_warnings.sh` fails on any compiler, linker, SwiftPM, CocoaPods, or `xcodebuild` warning and runs in CI.
* **Example Studio:** the atomic preset buttons no longer call `setState` after the widget was disposed.
* **Integration tests:** `example/integration_test` now covers the public API against the real native window on macOS, Windows, and Linux: state and `configure`, geometry, show and hide, maximize, minimize, fullscreen, behavior flags, the intercepted close, the event stream, the widgets, and the example Studio app. The suites run in one app launch through `plugin_integration_test.dart`.
* **Unit tests:** the models, the wire payload of every platform channel call, the controller, and the `DragArea` and `WindowResizeEdgeArea` pointer behavior are covered by `flutter test`.
* **CI:** GitHub Actions runs analyze, unit tests, the macOS warning gate, the macOS XCTest unit tests, and the integration tests on macOS, Windows, and Linux.

## 1.0.4

* **Min/max on programmatic resize:** `setSize`, `setBounds`, and `center(size:)` clamp to the stored minimum and maximum on macOS, Windows, and Linux. AppKit `setFrame` and Win32 `SetWindowPos` ignore those limits, so `setSize(500, 400)` after `setMinimumSize(850, 560)` previously kept 500×400. Linux `configure` now clamps the same way macOS and Windows already did. A non-positive limit leaves that edge open; if both are set and the maximum is below the minimum, the minimum wins.
* **Caption tests on macOS:** `WindowCaption` selects the macOS layout from Flutter's `defaultTargetPlatform` instead of `Platform.isMacOS`. `window_caption_test.dart` forces the Windows caption, so `flutter test` passes on a macOS host. macOS still hides the Windows-style minimize, maximize, and close buttons.
* **Example `hide()` on macOS:** the example `AppDelegate` returns false from `applicationShouldTerminateAfterLastWindowClosed`. `hide()` orders the window out, and the Flutter template's `true` quits the process, so `show()` never runs. Hosts that hide the window need the same override (see the README).

## 1.0.2

* **Material import:** `WindowCaption` now imports `package:material_ui/material_ui.dart`. `package:flutter/material.dart` is deprecated on Flutter 3.50 and produced an analyzer warning.
* **Narrow client areas:** `WindowCaption` clips an oversized title and hides or scales the trailing controls instead of painting a RenderFlex overflow when the window is only a couple hundred pixels wide (for example during a minimize animation). The example Studio cards scroll or ellipsize the same way.
* **Windows caption maximize:** a left click on the `WindowCaption` / `SnapLayoutButton` maximize control toggles maximize again. `WM_NCHITTEST` still returns `HTMAXBUTTON` so Windows 11 Snap Layouts can open on hover, but that non-client hit never reaches Flutter's `onTap`, and `WM_NCLBUTTONUP` was not a reliable release signal after the non-client press was swallowed. The plugin now arms the press, captures the mouse, and posts `snapButtonClicked` when the button is released inside the control. `SnapLayoutButton` still performs the default `toggleMaximize()` from that event.

## 1.0.1

* **Wayland drag**: `DragArea` and `WindowResizeEdgeArea` register their layout rects, and the Linux GDK filter calls `gtk_window_begin_move_drag` / `gtk_window_begin_resize_drag` inside the button-press event. GTK3 Wayland ignores the timestamp argument and sends the seat's implicit-grab serial, which compositors generally accept only during that dispatch. X11 still uses the async method-channel path, including the `GDK_CURRENT_TIME` fallback.
* **Wayland center**: an unmapped window still gets `GTK_WIN_POS_CENTER` before the first map (a hint the compositor may ignore). A mapped Wayland window is not moved — `xdg-shell` does not allow client absolute positions — and `center()` returns false instead of reporting a position GTK only cached. `WindowStateSnapshot.isPositionAuthoritative` is false on Wayland.
* A bare `startDragging()` / `startResizing()` call that arrives after the press is still best-effort on Wayland and is skipped when no button serial was captured.

## 1.0.0

* Initial production release of `xue_hua_navite_window_manager`.
* **Zero-Flash First Frame**: Eliminates startup black/white flash on macOS, Windows, and Linux by synchronizing native window backing color and deferring presentation until the first Flutter frame renders.
* **Atomic Window Configuration**: Single-pass `NativeWindowController.configure(WindowConfig)` sets size, min/max constraints, center/position, title bar style, background color, and traffic light offsets without visual jumping or multi-channel overhead.
* **Deep Custom Frame & Native Feel**:
  * Windows: Win32 `SetWindowSubclass` handling `WM_NCCALCSIZE`, `WM_NCHITTEST` (with 6-8px resize borders and `HTMAXBUTTON` support for Windows 11 Snap Layouts), `WM_GETMINMAXINFO`, `WM_ERASEBKGND`, and `DwmSetWindowAttribute` for native DWM shadow and rounded corners (`DWMWCP_ROUND`).
  * macOS: Full-size content view with transparent titlebar, custom `(x, y)` offset controller for traffic light buttons (`closeButton`, `miniaturizeButton`, `zoomButton`) across resize and fullscreen transitions, and Swift Package Manager (SPM) support.
  * Linux: GTK3 header bar and frameless CSD geometry management, edge resizing, and window state lifecycle tracking.
* **High-Performance Dragging, Resizing & Event Stream**: Native `startDragging()`, `startResizing(ResizeEdge)`, `DragArea`, `WindowCaption`, `SnapLayoutButton`, and real-time `EventChannel` state notifications.
